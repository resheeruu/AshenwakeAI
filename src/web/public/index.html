01ROUTING

One request. Every provider. A measured way out.

Every message is classified, budgeted, routed and observed before a single token leaves the box. When a provider degrades, the chain falls through instead of failing the channel — and the decision is logged either way.

◎
Classify before you spend
Tone, intent and tool demand are decided first so the cheapest capable model answers routine traffic.
⇄
Fallback that is actually wired
Provider health feeds the router; a degraded upstream rotates to the next candidate instead of erroring.
▤
Budgets are per server
Daily, monthly and per-minute limits live in the guild config, enforced before dispatch.
request path live

Policy + budget check
Rate limit, burst limit and remaining daily quota are evaluated before any provider is touched.

Model selection
Routing rules pick a candidate from the configured chain; capabilities are matched to the task.

02MODERATION

Policy first. The bot enforces what you wrote down.

Automod settings are plain, versioned configuration — readable in the dashboard, auditable on every change, and applied per server with no global surprises.

⛨

Automod that stays in its lane

Spam, flood, mention abuse, invites, scams, links, caps and zalgo each carry their own toggle and threshold. Nothing runs that you did not switch on.

anti-spamanti-floodanti-inviteanti-scamanti-linkanti-capsanti-zalgo
◷

Raid mode with real thresholds

Messages-per-window and mention ceilings are explicit numbers in config — 5 messages / 5000ms by default — not a hidden heuristic.

maxMentions 5maxMessages 55s window
⏱

Timeouts and warns

Default timeout minutes, warn ceiling before action, and an optional auto-ban at the limit.

⌗

Channel targets

Assistant, log, welcome and ticket categories are IDs you pick — never guessed by the bot.

⚑

Role-aware

Staff role IDs decide who reads the queue and who can act on it inside Discord.

03AUTOMATION

Rules you can read back.

Every rule is a trigger, a bounded condition set and a bounded action set — stored per server, written only by an owner with a CSRF token, and deleted cleanly when you are done.

✓
Owner-only writes
Create, update and delete all require owner plus a validated CSRF header.
▦
Bounded by construction
At most 50 conditions and 50 actions per rule, validated before anything is persisted.
✗
No shadow execution
Rules are authored and stored here. AshenAI does not silently fire them in the background — what you store is exactly what exists.
Anti-raid escalation enabled

›guild.member.joined

Conditions

›window ≤ 5000ms
›sender account age < 7d

›timeout member

Rules are stored per server and written only by an owner. AshenAI does not claim background execution for them.

09SECURITY

Assume the session is hostile.

The dashboard is a thin client over a gated API. Nothing renders because the page asked for it — it renders because a validated session and role said so.

L1 / SESSION

Sessions that rotate

HttpOnly, SameSite=Lax, Secure in production, 24-hour lifetime with idle rotation every hour.

  • ashenai_owner_sid
  • idle rotation 1h
  • server-side revocation
L2 / CSRF

Every mutation is signed

POST, PUT and DELETE demand a per-session token in X-CSRF-Token. GET never mutates.

  • per-session token
  • header-bound
  • logout is CSRF-guarded
L3 / ACCESS

Roles all the way down

Owner, admin and user are enforced in middleware — not by hiding buttons in the browser.

  • requireAuth
  • requireRole
  • requireGuildAuth
L4 / ACCOUNT

MFA and OAuth

TOTP with recovery codes, Discord and Google sign-in, and account linking that never puts identifiers in a URL.

  • TOTP + recovery
  • OAuth link flow
  • password reset tokens
L5 / OUTPUT

Nothing renders raw

One shared escape helper covers every API-sourced string, and secrets are redacted before they reach a log line.

  • escapeHtml everywhere
  • redact() on logs
  • secret scan on save
L6 / TRANSPORT

CSP without unsafe-inline

Nonce-only script policy, no inline handlers, no inline styles. The page you see is the page we shipped.

  • nonce-based scripts
  • no style attributes
  • no inline handlers
